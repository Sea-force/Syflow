# Форма обратной связи → письмо на почту

Состав:
- `main.py` — бэкенд на FastAPI, принимает данные формы и шлёт письмо по SMTP.
- `requirements.txt` — зависимости Python.
- `.env.example` — шаблон настроек (SMTP, получатель, разрешённые домены).
- `contact-form.js` — JS, который перехватывает отправку формы и шлёт данные на бэкенд.
- `form-fixed.html` — ваша форма с исправленным багом (у полей "Имя" и "Компания" был одинаковый `name="name"` — из-за этого компания никогда бы не отправлялась).

## Важно про Mail.ru

С 12 июня 2026 года Mail.ru требует платную подписку "Mail Space для работы", чтобы создать
"пароль для внешнего приложения" — то есть чтобы **логиниться по SMTP как syflow@mail.ru**.
Само получение писем на syflow@mail.ru через обычную веб-почту это не затрагивает.

Поэтому в примере ниже письма отправляются **от имени другого почтового ящика** (например, Яндекс),
а `syflow@mail.ru` указан только как получатель — это бесплатно и работает без ограничений.
Если у вас уже есть подписка Mail Space, можно вместо этого использовать сам syflow@mail.ru как
отправителя — соответствующий блок есть в `.env.example` закомментированным.

## 1. Установка

```bash
cd contact-backend
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Настройка SMTP-отправителя

Проще всего завести (или использовать существующий) ящик на Яндексе:

1. Зайдите на аккаунт Яндекс → **Пароли и авторизация** → **Пароли приложений**.
2. Создайте пароль приложения для "Почты".
3. Скопируйте полученный пароль — он понадобится в `.env`.

(Аналогично можно использовать Gmail с включённой двухфакторной аутентификацией и
паролем приложения, либо любой другой SMTP, включая корпоративную почту или
транзакционный сервис типа Resend/SendGrid/Mailgun.)

## 3. Настройка .env

```bash
cp .env.example .env
```

Откройте `.env` и впишите:
- `SMTP_HOST`, `SMTP_PORT` — сервер вашего почтового провайдера (для Яндекса уже подставлены).
- `SMTP_USER` — адрес ящика-отправителя.
- `SMTP_PASSWORD` — пароль приложения (НЕ обычный пароль от почты).
- `MAIL_TO` — `syflow@mail.ru` (уже стоит по умолчанию).
- `ALLOWED_ORIGINS` — домен(ы) вашего сайта, например `https://mysite.ru`. Это защита от того,
  чтобы форму с вашего API мог дёргать кто угодно с чужого сайта.

## 4. Запуск локально

```bash
uvicorn main:app --reload --port 8000
```

Проверка, что сервер жив:

```bash
curl http://127.0.0.1:8000/api/health
```

Проверка отправки письма:

```bash
curl -X POST http://127.0.0.1:8000/api/contact \
  -H "Content-Type: application/json" \
  -d '{
        "name": "Иван",
        "company": "ООО Ромашка",
        "email": "ivan@example.com",
        "phone": "+79990000000",
        "message": "Тестовое сообщение",
        "privacy_policy": true,
        "personal_data_consent": true
      }'
```

Если всё настроено верно, письмо придёт на syflow@mail.ru.

## 5. Подключение к сайту

1. Замените форму в вашем HTML на содержимое `form-fixed.html` (или просто исправьте
   `name="name"` на `name="company"` у поля "Компания" в своей текущей вёрстке).
2. Подключите `contact-form.js` на странице (уже подключён в `form-fixed.html` через `<script>`).
3. В `contact-form.js` замените `CONTACT_API_URL` на реальный адрес вашего бэкенда после деплоя,
   например `https://api.mysite.ru/api/contact`.

## 6. Деплой на сервер (кратко)

Бэкенд нужно где-то держать постоянно запущенным (localhost работает только у вас на компьютере).
Варианты:

- **VPS (например, timeweb, reg.ru, Selectel, Yandex Cloud и т.п.)**:
  - Скопируйте папку на сервер, установите зависимости как в шаге 1.
  - Запускайте через `systemd`-сервис или `pm2`/`supervisor`, чтобы процесс жил постоянно:
    ```bash
    uvicorn main:app --host 0.0.0.0 --port 8000
    ```
  - Настройте nginx как реверс-прокси с HTTPS (обязательно — иначе браузер заблокирует
    запрос с https-страницы вашего сайта на http-бэкенд, это называется mixed content):
    ```nginx
    server {
        listen 443 ssl;
        server_name api.mysite.ru;

        ssl_certificate     /etc/letsencrypt/live/api.mysite.ru/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/api.mysite.ru/privkey.pem;

        location / {
            proxy_pass http://127.0.0.1:8000;
            proxy_set_header Host $host;
        }
    }
    ```
  - SSL-сертификат можно бесплатно получить через `certbot` (Let's Encrypt).

- **PaaS без своего сервера** (проще всего для старта): Render, Railway, Fly.io — заливаете
  папку, они сами дают вам https-адрес и держат процесс запущенным.

После деплоя не забудьте:
- Указать реальный домен бэкенда в `CONTACT_API_URL` в `contact-form.js`.
- Указать реальный домен вашего сайта в `ALLOWED_ORIGINS` в `.env` на сервере.
